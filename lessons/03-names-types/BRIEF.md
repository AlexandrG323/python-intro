# Урок 3. Имена, типы, изменяемость

Цель: перестать думать о переменной Python как о ячейке памяти C++. Имя — ярлык на объекте. Некоторые объекты можно менять на месте, некоторые — нет.

## Карта

```
имя ──► объект (тип, значение, идентичность)
          list: можно менять содержимое
          int/str/tuple: содержимое не меняется, имя можно перевесить
```

`a is b` — тот же объект (как сравнение указателей).
`a == b` — равные значения.

`None` — один объект-синглтон. Проверка: `value is None`, не `value == None`.

Срез `xs[:]` у списка — **новый** список с теми же элементами (shallow copy). Присваивание `b = a` для списка — второй ярлык на тот же список.

`int` в Python не переполняется как `int` на Arduino (16/32 бита). Это объекты произвольной длины. Медленнее, зато без сюрприза `32767 + 1`.

Type hints (`x: int`) редактор и люди читают. Интерпретатор их по умолчанию **не проверяет** — в отличие от TypeScript.

## Аналогии

- C++: `int x` — ячейка; `int& r = x` — ссылка; `vector` vs копирование.
- TypeScript: `const xs = []; const ys = xs;` — та же мутация массива. Примитивы копируются по значению.
- Arduino `int`: переполнение. Python `int`: нет.

2. Почему `is` для маленьких чисел иногда «случайно» True, и почему на это нельзя опираться?
3. Чем hint `name: str` похож на TypeScript и чем нет?

## Упражнения

Файл `exercises/names_and_copies.py`:

- `is_same_object(a, b) -> bool` — через `is`.
- `is_none(value) -> bool` — через `is`, не через `==`.
- `shallow_copy(xs: list) -> list` — новый список, те же элементы. Исходный после `copy.append(...)` не меняется. Элементы-списки внутри — те же объекты.
- `mutate_last(xs: list, value) -> None` — заменить последний элемент на месте. Пустой список: `IndexError`.
- `swap(a, b) -> tuple` — вернуть `(b, a)` без мутации (распаковка).

# Урок 2. Как выполняется код

Цель: понять цепочку «текст → байткод → CPython», чем скрипт отличается от import и зачем `if __name__ == "__main__"`.

## Карта

```
.py  →  компиляция в байткод (.pyc в __pycache__)  →  CPython исполняет
```

Это не машинный код прошивки ESP32 и не `tsc` в JS. Интерпретатор читает байткод во время запуска. REPL (`uv run python`) — тот же интерпретатор, только строка за строкой.

`import greeter` выполняет файл **один раз** и кладёт имена в модуль. Повторный import берёт уже загруженный модуль (как кэш). Поэтому побочные эффекты на верхнем уровне файла опасны — они случатся при импорте, в том числе из тестов.

`__name__` у файла, который запустили как программу, равен `"__main__"`. У импортированного модуля — имя модуля (`"greeter"`). Отсюда страж `if __name__ == "__main__":`.

venv (у нас `.venv` через uv) — изолированный интерпретатор и пакеты. Аналог: `node_modules` + фиксированная версия Node, только для Python.

## Аналогии

- Arduino: Sketch компилируется в прошивку заранее. Ошибка типов часто на этапе сборки.
- TypeScript: `tsc` / Vite проверяют типы до браузера. Python проверяет большую часть вещей **в момент выполнения**.
- NestJS: `import` модуля с декораторами выполняется при старте приложения — тот же класс проблем, что и код на верхнем уровне `.py`.

## Упражнения

Все файлы в `exercises/`.

1. `greeter.py` — `greet(name: str) -> str` возвращает `Hello, {name}!` (запятая и пробел после Hello, восклицательный знак в конце).
2. `app.py` — `run(name: str) -> str` вызывает `greet` из `greeter` и возвращает тот же результат. Импорт — внутри модуля, не внутри функции, если не решите иначе осознанно.
3. `run_mode.py`:
   - `should_run_cli(module_name: str) -> bool` — `True` только если `module_name == "__main__"`.
   - `describe_run_mode(imported: bool) -> str` — `"library"` если `imported` истинно, иначе `"script"`.

# Урок 6. Функции и область видимости

Цель: `def`, аргументы по умолчанию, `*args` / `**kwargs`, область видимости LEGB, функция как значение.

## Карта

```
L — local      внутри функции
E — enclosing  объемлющая (замыкание)
G — global     модуль
B — builtin    len, str, ...
```

Имя ищется в этом порядке. Присваивание внутри функции создаёт **локальное** имя, если не сказано `global` / `nonlocal`. `global` почти всегда плохой знак — как глобальные в скетче Arduino, только ещё легче выстрелить в ногу.

Аргументы по умолчанию вычисляются **один раз** при создании функции. Не ставьте туда `[]` или `{}` — получите общий объект на все вызовы. Стандарт: `None` и создание списка внутри.

`*args` — лишние позиционные в кортеж. `**kwargs` — лишние именованные в словарь. В TypeScript похоже на rest `...args`.

Функция — объект. Её можно передать как колбэк (как в JS). Вложенная функция может замкнуть переменную объемлющей — так делают фабрики вроде `make_adder`.

`return` без значения возвращает `None`. Забыли `return` — тоже `None`, частая ошибка после C++ `void` vs значение.

## Аналогии

- C++: объявление + определение, перегрузка, шаблоны. В Python одна `def`, типы мягкие, перегрузка через `@overload` почти не нужна на этом уровне.
- TypeScript: `const add = (n) => (x) => x + n` ≈ замыкание `make_adder`.
- NestJS: сервис-метод с дефолтами в DTO vs дефолты в сигнатуре Python.

## Наводящие вопросы

1. Почему `def f(xs=[]):` ломается на втором вызове?
2. Чем `*args` отличается от передачи одного списка?
3. Если внутри функции написать `x = x + 1`, а снаружи есть `x`, что произойдёт и почему?

## Упражнения

Файл `exercises/functions_practice.py`. Константа `SCALE = 10` уже в файле — её читает `scaled`.

- `greet(name: str, greeting: str = "Hello") -> str` — `{greeting}, {name}!`
- `join_words(*parts: str, sep: str = " ") -> str` — `sep.join(parts)`. Без частей — пустая строка.
- `apply_twice(fn, x)` — `fn(fn(x))`.
- `make_adder(n: int)` — вернуть функцию `inner(x)`, которая даёт `x + n`.
- `scaled(x: int, scale: int | None = None) -> int` — если `scale is None`, взять модульный `SCALE`. Вернуть `x * scale`.
- `positive_only(xs: list[int]) -> list[int]` — новый список из элементов `> 0`, исходный не менять.
